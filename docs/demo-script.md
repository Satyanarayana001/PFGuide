# PFGuide — Two-Minute Demo Script

## Target Duration

Maximum: 2 minutes

Structure:

- First minute: citizen journey
- Second minute: how it was built and why

---

# 0:00–0:10 — Problem

"Understanding a PF claim status can be confusing. A user may see messages like employer verification incomplete or verification review without knowing what actually happened or what they should do next."

---

# 0:10–0:20 — Introduce PFGuide

"PFGuide is a prototype that turns a confusing claim status into a simpler citizen journey. It explains what happened, why it happened, and what the user can do next."

Show the welcome screen.

Click:

**Try the demo**

---

# 0:20–0:35 — Claim Overview

Show the claim overview.

"The user can immediately see the claim type, current stage, issue, document status, and submission date. Important information is presented clearly instead of requiring the user to interpret a technical status alone."

Click:

**Understand my claim**

---

# 0:35–0:50 — Plain-Language Explanation

Show:

- What happened?
- Why?
- What can I do now?

"Instead of leaving the user to figure out the next step, PFGuide explains the situation in simple language and provides actionable guidance."

Click:

**Prepare a grievance**

---

# 0:50–1:00 — Complete the Citizen Journey

Show the grievance draft.

"If the user still needs help, PFGuide prepares a draft based on the synthetic claim information. The user can review and edit it before submitting."

Submit the demo grievance and show the synthetic reference number.

"This completes the prototype citizen journey from confusion to a clear next action."

---

# 1:00–1:20 — How It Was Built

"PFGuide uses a React and Vite frontend with a FastAPI backend. The application uses synthetic claim data and simulated backend behavior because connecting to live government systems would be unsafe and outside the scope of this prototype."

---

# 1:20–1:35 — Codex Usage

"Codex was used throughout the development process for architecture, implementation, debugging, testing, frontend development, and iterative refinement. It was part of the actual build workflow."

---

# 1:35–1:50 — Why These Choices

"The main design decision was to simplify the experience around three questions: What happened, why, and what can I do now? The interface is designed to be mobile-friendly and understandable for users with different levels of digital experience."

---

# 1:50–2:00 — Honesty and Closing

"All information in this prototype is synthetic. PFGuide is not an official government service and does not connect to EPFO or any live government system."

"PFGuide demonstrates what a simpler and clearer citizen experience could look like."

---

# Demo Checklist

Before recording:

- Backend is running
- Frontend is running
- Browser zoom is comfortable
- Demo starts from the welcome page
- Synthetic data notice is visible
- Full journey is tested
- No real personal information is visible
- Recording stays under 2 minutes
